# Решения и допущения

**Решения там, где ТЗ неоднозначно**
- Смена статуса — только через функцию `change_task_status` (прямой `UPDATE` статуса запрещён правами на колонки).
- Роли хранятся в таблице `profiles`, клиент их менять не может. Новый пользователь — «исполнитель».
- Постановщик может править поля задачи (название, описание, объект, исполнителя) в любом статусе, кроме «Принята» — принятая задача заморожена.
- Исполнителем можно назначить только пользователя с ролью «исполнитель» (проверка в БД). Задачу можно создать без исполнителя; до назначения её видят только постановщики.
- Если задачу переназначили, прежний исполнитель теряет к ней (и к объекту, если других задач там нет) доступ.
- Постановщик «берёт в работу» и «отправляет на проверку» не может: по ТЗ это действия назначенного исполнителя.
- Принимать и возвращать на доработку может любой постановщик, не только автор задачи.
- В историю добавляется запись о создании задачи (из «—» в «Новая»).
- Удаление «мягкое»: удалённые объекты и задачи помечаются (`deleted_at`, `deleted_by`) и остаются в базе вместе с историей. Физически удалить их через API нельзя. Удалённое видят только постановщики, раздел «Удалённые» (только просмотр). Удаление объекта помечает удалёнными и его задачи. Исполнитель удалённые задачи и объекты не видит.
- Постановщик может восстановить удалённую задачу (из панели задачи) и объект (из раздела «Удалённые»). Задача удалённого объекта восстанавливается только вместе с ним: восстанавливаются задачи, удалённые в тот же момент, что и объект. Окончательная очистка не реализована (только вручную в базе).
- Исполнитель видит имена постановщиков (для отображения автора), но не других исполнителей.
- Объекты и задачи постановщика видны всем постановщикам.

**Не успел / упрощения**
- Нет автотестов UI; безопасность проверяется скриптом `scripts/security-check.mjs`.
- Нет пагинации и поиска/фильтров, списки загружаются целиком.
- Нет управления пользователями из интерфейса (по ТЗ — вручную в Supabase).
- Нет realtime: данные обновляются после действий пользователя.
- Не сделан аудит изменения полей задачи (только смены статусов).
